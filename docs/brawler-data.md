# COSMO и VINCE: данные и изображения

Проверено 28 октября 2026 года. Это дополнение к существующему каталогу,
а не новый игровой движок.

## Где что хранится

- `brawler_catalog.py` — встроенные дополнения к каталогу. `utils.load_brawlers_info()`
  объединяет их с сохранённой таблицей, сохраняя пользовательские настройки.
- `cfg/brawlers_info.json` — поставляемая таблица боевых параметров.
- `latest_brawler_data.json` — шаблон очереди для новой установки. Это не каталог
  и не список открытых бойцов аккаунта. Существующие очереди устройств не меняются.
- `api/assets/brawler_icons/` — локальные портреты для веб-панели, очереди и статистики.
  Старое имя папки `brawler_icons2/` также поддерживается.
- `webui/services.py` — список бойцов панели; `webui/app.py` — выдача изображений.
- `trophy_reader.py`, `lobby_automation.py`, `stage_manager.py` — распознавание имени,
  выбор бойца и подтверждение результата. Они уже используют общий каталог.
- `play.py`, `combat_behavior.py`, `super_policy.py`, `playstyles/` — существующая
  боевая логика. Её параметры и алгоритмы этим исправлением не менялись.

| Поле | COSMO | VINCE |

| Внутреннее имя игры | Attractor | Stacker |
| ID портрета (`avatarId`) | 28001337 | 28001338 |
| Редкость | Mythic | Mythic |
| Класс | Controller | Damage Dealer |
| Дальность атаки, `CastingRange` | 27 | 25 |
| Дальность суперспособности, `CastingRange` | 28 | 27 |
| Дальность гаджетов COSMO | 22 | — |
| `attack_range` в боте | 576 | 533 |
| `super_range` в боте | 597 | 576 |
| `gadget_range` в боте | 469 | — |

Конверсия существующего проекта: три единицы дальности игры соответствуют
одной клетке, а клетка — 64 пикселям опорного разрешения.
Дальность округляется до целого: например, 25 / 3 × 64 ≈ 533.
Дальность суперспособности VINCE одинакова у `StackerUlti` и уровней 1–3.

`safe_range` (460.8 для COSMO, 328 для VINCE) — существующая настройка поведения
бота, а не официальная характеристика. `hold_attack=0` и флаги стен оставлены
как в исходном проекте. Здоровье, урон, скорость и неизвестные параметры не
добавлялись: текущая логика не требует их для интеграции этих бойцов.
В новых строках шаблона очереди трофеи равны `null`: реальные трофеи аккаунта
неизвестны до измерения. Нули побед и серии — начальные счётчики бота.

## Доставка

Сборка `xlambot.spec` уже включает всю папку `api/assets`, отдельно менять её
не нужно. В существующем канале обновлений скрипты и изображения доставляются
раздельно: одного `scripts.zip` без новых PNG недостаточно. Обновлённый маршрут
поддерживает PNG из активного снимка ресурсов даже при отсутствии файла в старой
встроенной версии. Подписи и правила проверки обновлений не менялись.

Не заменяйте очередь, настройки, историю и профили работающей установки шаблонами
из архива. Исходники не содержат моделей ONNX, scrcpy и Tesseract: согласно README,
они берутся из установленной версии xlamBOT. Этот архив не является собранным EXE
или опубликованным подписанным обновлением.

## Исправление выбора на текущей карточке бойца

При проверке на устройстве обнаружился дополнительный отказ: на карточках VINCE
и COSMO серый значок невыбранного избранного отличается от прежнего шаблона.
`detail_home_position()` не подтверждал карточку, поэтому `detail_select_position()`
не разрешал нажатие «Выбрать». Восстановление меню затем возвращало игру в лобби.
В `brawler_detail_glyphs.py` добавлен только анонимный значок, без данных аккаунта.
Все независимые проверки остальных контролов и жёлтой кнопки сохранены.

Повторная проверка 29 октября выявила ещё один вариант — розовый заполненный
значок избранного. Он также добавлен отдельно: прежние шаблоны совпадали с ним
недостаточно точно, из-за чего нужный COSMO открывался, но кнопка «Выбрать»
не подтверждалась. Новый шаблон содержит только анонимный значок; порог
совпадения, проверка профиля, чата, дома и жёлтой кнопки не ослаблены.

Кроме того, `get_action_state()` мог ошибочно принять уменьшенную карточку за
магазин. Теперь для подтверждённой карточки используется полный классификатор
на исходном разрешении, включая прежний приоритет диалогов. Сроки годности кадров,
их отметки времени и проверка владельца ввода не менялись.

Ручной поиск также обновляет наблюдение после OCR имени и перед нажатием
карточки. Холодный запуск OCR мог занимать дольше допустимого возраста кадра;
теперь новый кадр повторно подтверждает список бойцов, как в автоматическом
выборе. При появлении другого экрана нажатие не выполняется.

На NITA повторный прогон также выявил ошибку OCR: настроенная область имени
захватывала часть рисунка рядом с короткой надписью. После прежних попыток
`trophy_reader.py` дополнительно читает белые буквы в той же области. Эта
дополнительная попытка принимает только точное имя из каталога, без нечёткого
сопоставления. Координаты пользователя и проверка требуемого имени перед
нажатием не меняются.
