# xlamBOT — исходники

Закрытый репозиторий разработки. Публичная сборка и установщик: https://github.com/Olegu621/xlamBOT.

Текущие исходники закрепляются тегом `bot-revision-N` при каждой публикации. `source-provenance.json` публичного пакета содержит конкретный commit и SHA-256 архива. `revision-24.json` относится только к исторической ревизии 24.

## Разработка

Windows, Python 3.13. Создайте виртуальное окружение и установите `pip install -r requirements.txt`. Скопируйте `models`, `scrcpy` и `vendor` из `_internal` установленного xlamBOT в корень проекта: веса и сторонние исполняемые зависимости распространяются через публичный установщик, а не через Git. Затем `python xlambot_launcher.py`. Для сборки EXE установите PyInstaller и используйте `python -m PyInstaller xlambot.spec`.

Настройки здесь — шаблоны. Токены, профили устройств, записи обучения и история матчей не публикуются. `cfg/login.toml` и `cfg/webhook_config.toml` редактируйте только локально, не коммитьте реальные значения.

Точка запуска EXE: `xlambot_launcher.py`; жизненный цикл веб-панели: `webui/app.py`; управление устройствами: `webui/device_manager.py`; отдельный рабочий процесс: `bot_instance.py`. Telegram подключайте к обычному жизненному циклу приложения, а не только к legacy `main.py`.

## Публикация

Работайте в отдельных ветках и объединяйте изменения через PR. Перед публикацией обновите `main` этого репозитория. Издатель запускает:

```powershell
python tools/publish.py --source . --source-repo . --key <локальный-ключ.pem> --revision <новый-номер>
```

Скрипт требует чистый `main`, синхронизирует исходники с GitHub, собирает подписанный пакет из сохранённого снимка и отправляет тег `bot-revision-N` с SHA-256 архива. Ошибка push останавливает публикацию. Повторное использование номера ревизии запрещено. `dist/N/source-provenance.json` связывает пакет с конкретным source commit.

Затем перенесите `manifest.json` и `scripts.zip` в публичный репозиторий, проверьте distribution CI и объедините PR. В Releases остаётся только установщик. Ключ подписи хранится только у издателя; исходники обновляются при каждой сборке, а не по таймеру.


## Классический игровой цикл (ревизия 34)

Игровое управление возвращено к циклу до переноса TrioSafety: движение плейстайла больше не переписывается глобальным арбитром, способности не блокируются по предположению о риске, а движение камеры не вычисляется на каждом кадре. Отдельный проверенный детектор газа и защита от устаревших команд сохранены. При пропуске игрока бот отпускает управление и не нажимает кнопки меню вслепую.

Ползунок Низкий → Стандарт → Средний → Высокий → Максимальный остаётся отдельным для каждого устройства. Уровни меняют частоту распознавания стен и газа и число направлений при поиске обхода; рекомендации не переключают режим автоматически. Уже сохранённые уровни и прежний выбор по умолчанию «Средний» сохраняются.

## Системный фикс — ревизия 55 / установщик 0.8.19

Наблюдения принимаются по порядку кадров. Фоновый классификатор больше не сбрасывает
нажатия, а решения проверяют смену экрана непосредственно перед вводом. Выбор бойца
может переходить между подтверждёнными меню; старое боевое решение этого права не имеет.
Награды обрабатываются короткими отменяемыми действиями одного рабочего потока.
Боковое меню распознаётся по нескольким значкам, слепое открытие меню из unknown убрано.

Запись результатов не зависит от 25-секундного интервала. Сбой модели газа останавливает
движение и включает ограниченные повторные попытки распознавания. Исправлены пути
профилей, параллельное сохранение настроек, списки классов и числовые/auto настройки.
Статистика изолирует повреждённые файлы, сохраняет неизвестные измерения и считает
график за один проход. Базовые трофеи привязаны к настроенному тегу аккаунта.
JS/CSS загружаются из того же подписанного снимка, что и сервер; отдельный канал
ресурсов используется для изображений и шрифтов.

Правила сопровождения: [AGENTS.md](AGENTS.md). Сборка и доставка нового запускающего
EXE: [installer/README.md](installer/README.md). Новый EXE не включает старый overlay
поверх своей более новой встроенной ревизии, даже если автообновления отключены.

Ограничения: автоматический канал скриптов не обновляет модели; смену игрового
аккаунта без смены настроенного тега нельзя достоверно определить по одному счёту.
Долгие реальные сессии, движение камеры и работа нескольких GPU-потоков требуют
отдельной проверки на устройствах; тесты не гарантируют отсутствие любых ошибок.
